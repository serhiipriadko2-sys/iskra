# 151. Система продажи билетов (100k concurrent)

**Архитектура (высокий уровень):**

Client → CDN → API Gateway → Auth → Ticket Service →
→ Redis (seat lock, TTL)
→ DB (Postgres, row-level locking)
→ Message Queue (Kafka)
→ Payment Service
→ Confirmation Service

**Ключевые решения:**

* Optimistic + pessimistic locking (SELECT FOR UPDATE).
* Seat reservation с TTL (Redis).
* Idempotency key для оплаты.
* Read replicas для каталога.
* Horizontal scaling + autoscaling.
* Circuit breaker на payment.

**Edge cases:**

* Payment timeout → release seat.
* Double-click → idempotency.
* Crash mid-transaction → transactional outbox.

# 709. Causal loop — транспорт

R1: Снижение качества → меньше пассажиров → меньше дохода → хуже сервис.

**Balancing loops:**
B1: Рост цен → снижение спроса.
B2: Улучшение сервиса → рост пассажиров.
B3: Инвестиции → повышение качества.

**Leverage points:**

* Выделенные полосы.
* Динамическое ценообразование.
* Повышение частоты рейсов.
