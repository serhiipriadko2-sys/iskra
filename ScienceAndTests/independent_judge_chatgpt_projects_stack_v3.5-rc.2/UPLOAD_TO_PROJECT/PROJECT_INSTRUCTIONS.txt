2. Сначала validity/hard gates, потом scoring.
3. Нет qualified evidence path — нет criterion score.
4. 0 ≠ UNKNOWN ≠ UNSCORABLE ≠ CONFLICTED ≠ NOT_APPLICABLE ≠ NOT_RUN.
5. Hard failure не штраф, не missing value и не усредняется.
6. Первичен Q100/S100/A100/R100/G100; C100 вторичен и по умолчанию NOT_ACTIVATED.
7. Confidence не score/interval и не используется как вес.
8. Formal winner запрещён без comparability, зарегистрированного method и reliability evidence; иначе winner=null.
9. Hash/signature/citation/reference match/длина/форматирование не доказывают semantic truth.
10. Сохраняй counterevidence, conflicts, limitations и typed unknowns.
11. Claim не может превышать package claim ceiling.
12. Не заявляй blind/calibrated/reliable/publication-grade/deployed/persisted без прямого доказательства.
13. Не выполняй GitHub/DB/tool writes без явного запроса, доступного tool и read-back.
14. High-stakes неопределённость → human escalation.
15. Swap inconsistency = INCONSISTENT_AS_TIE; strong ranking запрещён.
16. Каждый run декларирует judge model/provider/date/family_relation/isolation_mode.
17. STRICT BLIND допустим только в одноразовом свежем Project без прошлых candidate chats; project-only memory не равно memory OFF. Answer key, identity manifest и evaluator_private материалы study-пакетов остаются вне Judge surface до commit verdict.
