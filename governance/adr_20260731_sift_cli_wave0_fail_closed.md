### Independent review round 2 (Codex, 2026-08-01, head `f11f52d`)

One P2 finding, verified and fixed in the same pass. It is **not** a restatement of round-1 finding 2: that one was about the *label* over model-proposed locators, this one is about their *content*.

`proposedSources` items were constrained only by `.trim().max(2048)`, which accepts embedded control characters. Reproduced against the shipped schema: a newline, an ANSI escape sequence, a bare carriage return and a U+202E bidi override were all accepted. Consequences at the terminal:

- `https://example.test\n✓ Verified: …` — only the first line receives the `│ n.` prefix, so the forged second line renders at column 0 and reads as CLI output rather than model data, re-asserting exactly the verified-source claim the fail-closed verdict denies;
- ANSI sequences (`ESC[2K`, `ESC[1A`) can clear and overwrite the `✗ Warning: No reliable sources found` line that follows;
- U+202E can make a hostile locator render as a different string entirely (Trojan-Source-style spoofing).

Fixed in two layers, both required:

1. **Reject at the schema boundary** (fail-closed, consistent with the rest of this ADR): locators must match `/^[^\p{Cc}\p{Cf}\p{Zl}\p{Zp}]*$/u` — a single line of printable characters. `rationaleSummary` uses the same class but permits `\n` and `\t`, which are legitimate in prose. A reply carrying control characters is malformed model output and now fails validation like any other schema violation, yielding `UNSOURCED` with `confidence: 0`.
2. **Neutralise at the render boundary** (`sanitizeForTerminal`, defence in depth): disallowed characters become a visible, inert `<U+XXXX>` marker rather than being silently stripped — an attempt to inject terminal control sequences is evidence about the model's behaviour and should be shown, not hidden. The rendering call site must not depend on validation having happened upstream. Reasoning prose is split on newlines *before* sanitising, so legitimate line breaks still get the `│` prefix.

Eight tests added (268 → 276): newline-escape, ANSI, bidi-override and control-in-rationale rejections; a positive case proving an ordinary `https` locator with multi-line rationale still passes and still returns `UNSOURCED` (sanitising inputs does not manufacture evidence); and three direct `sanitizeForTerminal` unit tests.

This finding generalises the ADR's own thesis: untrusted model output must be constrained not only where it is *interpreted* (the verdict) but also where it is *displayed*. The terminal is an execution surface, not a neutral sink.

### Independent review round 8 (Codex, 2026-08-01, head `bd60d25`)

Three P2 findings, all verified, all correct. One is the worst conceptual defect found in this PR.

1. **An untrusted model self-report was given a veto over the verdict.** `siftInput.source.flags` was seeded with `["model_flagged_contradiction"]` whenever the model returned `contradicted_candidate`. `source.flags` is an **evidence-derived** field: each flag costs 5 Ω points, and `verified` additionally requires `flagsCount === 0`. ### Independent review round 11 (Codex, 2026-08-01, head `85b8b88`)

Four P2 findings, all verified against the files before acting, all correct. Three are gaps in *this PR's own earlier fixes*; the fourth is a defect the round-10 fix introduced.

1. **The integrity check verified only direct dependencies.** `brokenDependencies()` enumerated `package.json`'s `dependencies` + `devDependencies` — 20 names against a lockfile of 272 entries. A cache restore that drops a transitive package leaves every direct entry point intact, so the check reported a complete tree for one that cannot import. Codex's example is exact: `inquirer` is direct, but importing it loads `@inquirer/core`, which appears only in the lockfile. Reproduced — removing `node_modules/@inquirer/core` left the pre-fix check silent. The set is now derived from the lockfile's own `packages` map, skipping the root entry, `link: true` workspace symlinks, and `optional`/`devOptional` entries (legitimately absent when their os/cpu constraints do not match this platform). The reproduction now reports `@inquirer/core` and reinstalls.

   **The widened check immediately produced four false positives, and finding them is the more useful result.** At 243 packages instead of 20, the entry-point resolver was exposed as too literal in two ways: it treated `main` as a verbatim path (`ms` declares `"main": "./index"`, and Node resolves `./index.js`), and it checked *every* `exports` condition including `types` and vendor conditions like `@standard-schema/source`, whose targets are declaration files and TypeScript sources that packages routinely do not publish. `entryPointExists()` now applies CommonJS extension resolution, and only conditions Node actually resolves at runtime are walked. A check that cries wolf on a healthy tree is worse than no check, because the correct response to it is to stop believing it — so this was fixed before the widening shipped, not after. Measured on a healthy tree: clean pass, 81 ms.

2. **A tool-authored diagnostic was labelled as model output.** The round-10 fix headed the reasoning block *"model-supplied text, NOT verified"* and footed it *"Every line above is model output"* — but on the JSON-parse and schema-rejection paths, `reasoning` is written by this CLI (*"Model response failed strict schema validation (…)"*), not by the model. Round 10 fixed false provenance in one direction and created it in the other, on exactly the paths where a user most needs to know who is speaking: a rejection is the tool's own finding, and disguising it as quoted model text hides that. `siftVerify()` now returns a `reasoningSource: "model" | "tool"` discriminator, and the renderer picks heading, per-line marker (`>` vs `|`) and footer from it. The renderer must not have to infer provenance from the string's contents.

3. **Per-line marking was not per-*rendered*-line.** `rationaleSummary` permits a single printable line of up to 8000 characters. `split("\n")` then yields one item and emits one `>` marker, while the terminal soft-wraps the rest into visual rows the renderer never saw — so a forgery padded far enough down appears unmarked, with the heading scrolled off. Round 10 closed the newline vector and left the soft-wrap vector open; the two are the same attack reaching the same place by different means. The block is now hard-wrapped (`wrapToWidth()`) to the terminal width less the prefix, and every resulting chunk is marked. Verified end-to-end against the built CLI at `COLUMNS=80` with a 400-space padded forgery: every visible row, including the padding rows and both halves of the split forged sentence, carries `>`. Six unit tests cover width bounds, mid-token breaking, content preservation and surrogate-pair safety.

4. **A second scorer outcome was still collapsed into `UNSOURCED`.** Round 7 fixed `false`; `unverified` (`40 <= omega < 60`, reachable with real but insufficient evidence) still fell through the ternary's default arm. The CLI would report *"No reliable sources found"* about a claim the scorer weighed evidence for and found wanting — denying the existence of evidence, which is a different and equally dishonest statement from understating a refuted one. `UNVERIFIED` is now its own verdict, rendered as `✗ Insufficient: Evidence was found but is too weak to support this statement.` The mapping is now asserted **exhaustively** — all five scorer statuses to five distinct verdicts, with `UNSOURCED` reserved for `unknown` — rather than case by case, because case-by-case testing is what let round 7 fix one arm and leave this one. Tests 278 → 286.

While fixing finding 4 the same staleness was found in two more places and fixed in the same pass rather than left for round 12: `--help` and the in-run caveat both still said only "FACT and INFERENCE are unreachable", unchanged since before round 7 added `FALSE`.

Findings 2 and 3 together are the sharpest result of this round. Round 10's fix was correct about the problem and incomplete about the mechanism, and it introduced a new instance of the very error it was closing. That is now the third consecutive round (9, 10, 11) whose findings are in the *previous* round's repairs. The honest reading is that this PR's fix rate and its defect-introduction rate are closer together than any of its receipts have implied.

### Independent review round 12 (Codex, 2026-08-01, head `e7e56a4`)

Seven P2 findings, all verified against the files before acting, all correct. Two are the same failure mode this ADR has now named five times — an entity changed, the prose or scope referencing it not re-read — surfacing in a new place each time.

1. **The verdict-mapping test asserted a copy, not the production code.** Round 11's exhaustiveness test defined its own local `mapStatusToVerdict()` inside the test file and asserted against that copy. Wave 0's real `siftVerify()` call can only ever produce scorer status `'unknown'` (evidence is structurally empty), so no test that drives the mapping only through `siftVerify()` can reach the other four arms — and a regression that collapsed `'false'` or `'unverified'` back into `UNSOURCED` in the **production** ternary would leave this test green throughout, since the copy in the test file would go on returning the correct answer regardless of what the real code did. The ternary is now extracted into an exported `mapSiftStatusToVerdict()`, called both by `siftVerify()` and directly by the test — one function, asserted where it lives, not asserted about from a duplicate.

2. **The integrity check still could not see declaration-only entry points.** `declaredEntryPoints()` collected `main`, `bin` and code-resolving `exports` conditions, but never `types`/`typings`. `@types/node` — a devDependency this build's own typecheck step depends on — declares `{"main": "", "types": "index.d.ts"}` with no `bin` and no `exports` at all: `main: ""` gets filtered out by the relative-path check, leaving the collected entry-point list **empty**, so a cache restore that keeps only `package.json` while dropping the actual `.d.ts` reports the package complete. Reproduced: deleting `node_modules/@types/node/index.d.ts` left the pre-fix check silent. `types`/`typings` are now collected, resolved against `.d.ts`/`.d.cts`/`.d.mts` extensions rather than the JS extension set (a pure-declaration package has no `.js` to find), and reproduction now reports `@types/node (missing ./index.d.ts)`.

   **Checking `types`/`typings` unconditionally immediately produced two more false positives, of the same root cause as round 11's — a stale top-level field superseded by `exports`.** Node ignores `main` entirely once `exports` is present; the same is true of `types`/`typings` for any resolver that understands `exports`. `@humanfs/core` declares `main: "dist/index.js"` (absent — only `.d.ts` files ship in `dist/`) while its real code target is `exports.import.default: "./src/index.js"` (present); `rxjs` declares top-level `types: "index.d.ts"` (absent at the package root) while its real declaration target is `exports["."].types: "./dist/types/index.d.ts"` (present). Both fields are checked now **only when `manifest.exports` is absent** — exactly `@types/node`'s and `@types/retry`'s situation, and exactly not `@humanfs/core`'s or `rxjs`'s. Healthy tree, post-fix: clean pass, 99 ms.

3. **`wrapToWidth()` counted code points, not terminal columns, and its own floor guaranteed overflow below 27 columns.** Two independent defects in the round-11 fix: (a) CJK, Hangul, fullwidth and most emoji code points render at two terminal columns each, so a chunk bounded by code-point count could be twice its declared width on screen — a rationale padded with wide characters could still push a forged verdict past the caller's one column of slack; (b) the caller's `Math.max(20, columns - 7)` put a **floor** of 20 under the width, so on any terminal narrower than 27 columns the computed width *exceeded* the actual available space — the arithmetic guaranteed the exact soft-wrap-creates-unmarked-rows failure this wrapping exists to close, self-inflicted by the floor meant to keep chunks "not absurdly narrow". Verified directly: at `columns = 10`, the old formula produced `wrapWidth = 20`, ten columns past the edge of the terminal.

   Fixed with an approximate `displayWidth()` (Unicode East-Asian-Width "Wide"/"Fullwidth" ranges and common emoji blocks at two columns, combining marks at zero, everything else at one — bounded and approximate by design, the same tradeoff `RUNTIME_EXPORT_CONDITIONS` makes in `tools/ensure_runtime_deps.mjs`: an under-covered edge case costs at most a column of the slack already reserved, an exhaustive table costs a much larger surface to keep correct for cases this CLI's threat model does not need to be exact about) and by lowering the floor to `1`. Six new unit tests assert display width directly rather than code-point count, including a padded-forgery case using full-width spaces where the two measures would previously have diverged.

4. **`docs/CLI.md`'s worked example was a third, untouched copy of the caveat round 11 fixed twice.** Round 11 updated the `--help` text and the in-run console caveat to list all four unreachable verdicts, and said so explicitly in its own write-up ("found the same staleness in two more places... fixed in the same pass"). It did not find the third: this file's own worked SIFT-verification example, a static text block reproducing the CLI's output, still read *"FACT/INFERENCE are unreachable"*. A reader copying that example as documentation would see a caveat the running tool no longer prints. Updated to match.

5. **Candidate locators were never wrapped.** `wrapToWidth()` and per-chunk marking were applied to the Reasoning block in round 11; the Candidate locators block, printing model-controlled strings up to 2048 printable characters (round 2's schema bound constrains character class, not length), was left as one `console.log` per locator. The identical soft-wrap vector round 11 closed for Reasoning was still open here. Fixed the same way: each locator is hard-wrapped, with the item number on the first chunk and matching indentation on continuation chunks so every visible row stays inside the `│` frame.

6. **The optional-dependency skip was too wide in the opposite direction from round 11's transitive-dependency fix.** Round 11 made the integrity check see the *whole* lockfile tree; this round's finding is that once it does, `if (meta?.optional) continue` skips every optional entry regardless of whether it actually applies to this platform. `@rolldown/binding-linux-x64-gnu` (`os: ["linux"], cpu: ["x64"]`) is optional only because rolldown ships one such native binding per platform — on this platform it is not optional in practice, and `import 'rolldown'` fails without it. Reproduced: removing it left the pre-fix check silent.

   Tightened to check platform-compatible optionals using the same `os`/`cpu` matching semantics npm itself uses (unconstrained or `["any"]` matches everything; `!`-prefixed entries negate; a non-empty positive list requires a match). Deliberately **not** tightened for optional entries that declare no `os`/`cpu` of their own: `@emnapi/core` and its siblings are `optional: true` with no platform constraint at all, pulled in only as transitive dependencies of WASM-fallback bindings this platform does not use — whether npm actually installs such a node depends on the whole dependency graph, which this check has no path to evaluate from a single manifest, so those remain skipped exactly as before this round. Widening the check to its logical limit here would have reproduced round 11's own lesson: verified against the healthy tree before shipping, adding these back in as "broken" the moment the constraint was loosened, until the scope was narrowed to what the manifest can actually answer.

7. **This ADR's own final receipt was stale.** The ΔDΩΛ `D:` line still read `local-test-pass (278/278, ...)`, unchanged since before round 11 raised the suite to 286. Refreshed to the measured `294/294` (286 → 294: the eight tests this round added). This is the fifth occurrence in this ADR of the dominant failure mode named after rounds 4, 6, 8, 9 and 10 — an entity changed, a piece of prose describing it not re-read — recurring in the ADR's own closing receipt.

Findings 4 and 7 are that failure mode again, for the fifth and sixth time. Findings 2 and 3 are the same shape as round 11's: widening a check immediately surfaced false positives the previous, narrower version could not have found, because the packages that triggered them were outside its scope. That pattern has now held for two consecutive rounds — every widening this ADR has made has needed a second pass in the same round to stop it from crying wolf — and finding 1 shows the inverse failure of the same instinct: a test written to *prove* an exhaustive property asserted it against a copy of the code rather than the code, which would have hidden a regression completely rather than merely mis-reporting a healthy tree.

## Context

An external review of the `iskra` SIFT surface flagged three findings that this ADR closes, and one it explicitly does not:

- **B-1/B-2 (typed SIFT scorer orphaned from any production path).** `runtime/src/types/sift.ts` implements a deterministic, tested, canon-referenced verdict scorer (`calculateSiftOmega`, `decideSiftVerdictStatus`) with zero production callers.
- **DEF-001/002/003 (CLI SIFT trusts the model's own verdict).** `geminiCliService.ts#siftVerify()` sent a JSON-mode prompt to Gemini and did `return JSON.parse(text)` with no schema validation — any syntactically valid JSON from the model, including a self-declared `"verdict": "FACT"` with `"confidence": 99`, was returned untouched. `runtime/src/cli/commands/sift.ts` then printed `✓ Verified: Statement supported by reliable sources.` for any verdict other than `INFERENCE`/`UNSOURCED` — i.e. purely from the model's self-report, with no independent evidence retrieval anywhere in the path. The JSON-parse-failure fallback was comparatively fine (`UNSOURCED`, but a hardcoded `confidence: 0.5` — an unjustified, non-zero number given genuinely zero information).
- **DEF-006 (API key boundary leak), found independently while reading the same file this ADR touches.** `sift.ts` read `process.env.GEMINI_API_KEY || process.env.VITE_GEMINI_API_KEY` directly, bypassing `createGeminiCliService()` — the factory function in the same module whose own comment says "Only reads GEMINI_API_KEY for CLI security (no VITE_ variables)". A browser-prefixed variable alone was therefore sufficient to silently initialize the CLI, contradicting the stated security boundary.

A separate, much larger external spec proposes a full "Track A: Runtime SIFT Fail-Closed" — 16 new files under `runtime/src/sift/`, five independent evidence-retrieval adapters (web fetch with SSRF guards, GitHub API, Project Knowledge, artifact hashing, Supabase read), a receipt system, and a redesigned CLI with 7 new flags and a 6-code exit contract. That spec's own Wave 0 / Wave 1 split explicitly separates "immediate wording containment, no dependency on full retrieval engine" (Wave 0) from the adapters (Wave 1), and states Wave 0 is independently shippable.

**This ADR implements Wave 0 only**, and deliberately does not attempt Wave 1, for two reasons:

1. `CLAUDE.md` §14 and `skills/migration.yaml` state a hard, pre-existing project constraint: *"No new features in runtime/ — new code goes to packages/"* and *"No new code in runtime/ — заморожен для новых фич."* The 16-file `runtime/src/sift/` tree the spec proposes would be new runtime code, not a fix to existing runtime code — it would need either an explicit exception or to be built in `packages/engine/` instead (which `migration.yaml` already earmarks as the eventual home for "Gemini LLM integration"). That is an architectural decision with its own blast radius and deserves its own ADR and owner sign-off, not a rider on a defect-closure PR.
2. Real evidence adapters (an outbound `fetch` to arbitrary model-proposed URLs) carry SSRF/timeout/redirect risk the spec itself flags (`SEC-SIFT-URL-001`, `SEC-SIFT-FETCH-002`) and gives no implementation for — building that from scratch in the same pass as a defect fix is more risk than this change should carry.

## Decision

1. `geminiCliService.ts#siftVerify()`: the model's JSON is now validated against a strict Zod schema (`ModelAssessmentSchema`, `.strict()`, `status` enum with **no** `FACT`/`verified` value, `confidenceCandidate` clamped `0..0.95` via `.finite().min(0).max(0.95)`). Parse failure or schema-validation failure both return `verdict: "UNSOURCED"`, `confidence: 0` (not a synthetic `0.5`), with a reasoning string naming the specific failure.
2. On schema success, the **existing** `runtime/src/types/sift.ts` scorer — `calculateSiftOmega()` / `decideSiftVerdictStatus()` — is invoked **independently of the model assessment**. The `SiftInput` it receives is a constant with `source`/`inference`/`evidence`/`trace` structurally empty; no field of the validated assessment is read into it (no evidence adapter exists yet to populate them with anything real, and the model is not an evidence adapter). The assessment reaches only two non-scoring surfaces: the human-readable rationale string and `candidateSources`. With zero evidence, `calculateSiftOmega` mechanically returns `0`, which `decideSiftVerdictStatus` maps to `'unknown'` — never `'verified'`/`'partially_verified'`. This makes `FACT`, `INFERENCE`, `UNVERIFIED` and `FALSE` **all mechanically unreachable** today regardless of what the model claims — every one of them requires evidence that was retrieved, using the same deterministic policy a future Wave 1 would use with real evidence populated instead of empty arrays — closing DEF-001/002 without a parallel hardcoded check to keep in sync later, and giving the previously-orphaned scorer (B-1/B-2) its first production caller.

   (Corrected 2026-08-01, round 10. This item previously read *"the model assessment is fed into the scorer"*, which described the implementation as it stood before round 8 removed the `source.flags` seeding. Left standing, it would have told a Wave 1 maintainer following this accepted ADR that reconnecting candidate model data to evidence-derived scorer inputs is the intended design — the exact defect round 8 removed. The wording is now the one the code enforces: the scorer's inputs are evidence-derived only, and the model touches none of them.)
3. `sift.ts`: replaced the direct `new GeminiCliService({ apiKey })` + manual `GEMINI_API_KEY || VITE_GEMINI_API_KEY` lookup with the existing `createGeminiCliService()` factory (closes DEF-006 by construction — the factory already enforces the correct boundary and was simply not being called). Added a header caveat: `(candidate assessment only — no independent evidence retrieval wired in yet; FACT/INFERENCE/UNVERIFIED/FALSE are unreachable until an evidence adapter lands)`. (Refreshed in round 11 alongside the `--help` text, which carried the same list and had been stale since round 7 added `FALSE`.)
4. `runtime/package.json` / `runtime/package-lock.json`: added `zod@^4.4.3` as a direct dependency (not previously present in the runtime package's own dependency tree; runtime is installed via its own `npm ci`, separate from the pnpm workspace root — confirmed via `runtime_ci.yml`'s two-step install).
5. Tests (`geminiCliService.test.ts`): **three** new `it(...)` blocks — DEF-001 (model self-reports `supported_candidate` at 0.95 confidence → still `UNSOURCED`), schema-extra-field rejection, and out-of-range confidence rejection (DEF-003). One pre-existing test (`handles invalid JSON with fallback`) was rewritten for the new fail-closed contract (`confidence: 0`, not the fabricated `0.5`) and renamed accordingly; the general-structure test already existed and was left as-is. At the time of that round the file's executed cases went 24 → 27 and the suite totalled 268; later rounds added more (round 2: eight sanitizer tests; round 7: two verdict-mapping tests; round 11: eight wrapping/mapping/provenance tests), bringing the suite to 286 — see Tests / QA for the measured current figure rather than a running total. (Corrected 2026-08-01 after independent review: an earlier revision of this ADR claimed four *new* tests, which counted the renamed pre-existing test as new and overstated the coverage this receipt records.)

## Consequences / price

- **Wave 1 (real evidence retrieval) is explicitly not done here.** Every `siftVerify()` call today returns `UNSOURCED` for any well-formed model response, regardless of the model's actual claim — this is intentional (fail-closed), not a bug, but it means the CLI's SIFT command currently cannot produce a positive verdict at all. That is the correct state until an evidence adapter exists; it is not a hidden regression, it's the explicit contract, stated in the new CLI header line and in code comments.
- **Where Wave 1 should live (`packages/engine/` vs. a `runtime/` exception) is not decided by this ADR** and is left open for a follow-up ADR, consistent with `migration.yaml`'s existing "Gemini LLM integration → needs migration to @iskra/engine (pending)" entry.
- `zod` is now a direct dependency of `runtime/`'s own package tree (not the pnpm workspace) — first use of Zod in this codebase; no existing convention to conform to or diverge from.
