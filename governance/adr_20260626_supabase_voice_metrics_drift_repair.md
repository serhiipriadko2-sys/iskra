# ADR 2026-06-26: Supabase voice and metrics drift repair

## Context

Read-only live checks against `AgiIskra / typcvaszcfdpkzbjzuur` on 2026-06-26 found that the live public schema lagged behind the repo/runtime voice contract:

- `voice_preferences_voice_name_check` allowed eight voices and omitted `SIBYL`.
- `chat_history_voice_name_check` also allowed eight voices and omitted `SIBYL`.
- `metrics_snapshots` did not include `foresight`.
- `metrics_snapshots` defaults were `rhythm=75`, `trust=0.8`, `clarity=0.7`, `chaos=0.3`, while the runtime baseline is `rhythm=60`, `trust=0.7`, `clarity=0.8`, `chaos=0.2`, `foresight=0`.

The current repo schema snapshots already allowed `SIBYL` in both voice constraints, so the voice constraint issue is live-schema drift, not current repo canon.

## Finding / Decision

Add and apply a Git migration that:

- replaces both affected voice CHECK constraints with a nine-voice contract including `SIBYL`;
- adds `metrics_snapshots.foresight REAL DEFAULT 0`;
- aligns metric defaults with the runtime baseline.

Keep the statement "SIBYL is dead" out of the database repair scope. The confirmed defect is schema drift and missing persisted metric support, not proof about all runtime or canon behavior.

## Evidence

- Live before snapshot at `2026-06-26T14:04:16.590714+00:00` showed both voice CHECK constraints without `SIBYL`.
- Live before snapshot showed `metrics_snapshots` defaults `rhythm=75`, `trust=0.8`, `clarity=0.7`, `chaos=0.3`, and no `foresight`.
- Live row counts at the same snapshot were `chat_history=0`, `memory_nodes=0`, `graph_edges=0`, `graph_nodes=8`.
- Fresh live before snapshot at `2026-06-26T14:10:05.848518+00:00` confirmed the same pre-migration drift.
- Live after snapshot at `2026-06-26T14:10:54.562997+00:00` showed both voice CHECK constraints include `SIBYL`, `metrics_snapshots.foresight` exists with default `0`, and defaults are `rhythm=60`, `trust=0.7`, `clarity=0.8`, `chaos=0.2`.
- Live row counts after migration remained `chat_history=0`, `memory_nodes=0`, `graph_edges=0`, `graph_nodes=8`.
- Supabase migration history recorded `voice_metrics_drift_repair` as version `20260626141034`.
- Runtime baseline source: `runtime/src/types/metrics.ts`.

## Risk

The migration changes metadata only and does not insert, update, or delete user rows. The main risk is live-production DDL timing: applying it must be explicit and verified, because ledger integrity over repo files does not prove live Supabase semantic alignment.

## Next

Keep the repo migration file aligned with the live Supabase migration history version. Continue treating future live DDL as approval-gated.

Add a separate drift gate so this class of mismatch does not hide behind ledger success again:

- `pnpm check:supabase-voice-metrics-contract:repo` verifies the two repo schema mirrors agree.
- `pnpm check:supabase-voice-metrics-contract` compares repo schema mirrors with live DB metadata through `SUPABASE_DB_URL` / `DATABASE_URL` or a read-only JSON snapshot generated by the gate SQL.
- This gate is separate from `pnpm verify`; it requires an explicit live credential or snapshot and must not store secrets in repo files.
